     Реалізація

     1. PostToolUse (Edit|Write). Читає stdin JSON → tool_input.file_path.
     Розширення не з {.ts,.tsx,.js,.mjs,.json} → exit 0
     без перевірок (docs-only правки нічого не запускають). Немає file_path/JSON
     не парситься → fail-safe: запускати перевірки.
     Далі як §1: немає package.json/node_modules → skip exit 0; інакше
     typecheck+lint, діагностика у stderr, exit 2.
     Команда: node "$CLAUDE_PROJECT_DIR/scripts/agent-hook-check.mjs"; timeout: 
     120.

     2. Pre-commit. npm run typecheck && npm run lint && npm run test; git add 
     --chmod=+x; активація npm run prepare
     (лише локальний .git/config).

     3. Guardrail (permissions.deny), кожен патерн перевіряється окремо:
     Bash(git commit --no-verify*), Bash(git commit * --no-verify*), Bash(git 
     commit -n*), Bash(git commit * -n), Bash(git commit * -n *).
     Відомі прогалини (git -c core.hooksPath=… commit, складені команди a && git
     commit --no-verify) — зондуються й
     документуються як обмеження, а не ховаються.

     4. Stop hook. Повний npm run check (включно з e2e), timeout: 600.
     - Без відбитків/стампів. Вирішальний фільтр — git status --porcelain=v1 -z 
       --untracked-files=all: relevant = будь-який шлях
       зміни, що не під docs/ і не *.md. Охоплює staged, unstaged, untracked
       (кожен файл окремо), deleted (D) і renamed/copied
       (R/C: у -z це два токени — обидва шляхи перевіряються, relevant якщо хоч
       один relevant). Джерельний код, тести, конфіги,
       scripts/, .githooks/, .claude/settings.json, package*.json — relevant;
       .md (вкл. CLAUDE.md, .claude/agents/*.md) і docs/** — ні.
       Нерелевантні/порожні зміни, а також відсутні package.json/node_modules →
       exit 0.
     - Trade-off (документувати в §6): після коміту дерево чисте → Stop не
       запускає check. Закомічений код уже пройшов
       typecheck+lint+test у pre-commit; build та e2e для нього гарантує лише CI
       (Phase 3) і правило CLAUDE.md «npm run check перед
       завершенням». Тож Stop — страховка для незакомічених змін, а не повна
       гарантія e2e на кожен хід. Виграш: нуль стану, нуль
       хибних пропусків через відбиток, e2e не ганяється на Q&A/doc-ходах.
     - Допоміжний прапор AGENT_STOP_CHECK_DRY_RUN=1: друкує рішення (run/skip +
       причина) і виходить з 0 без запуску check —
       лише для швидкої перевірки фільтра.
     - Pass → exit 0.
     - Fail, stop_hook_active=false → діагностика (хвіст виводу провалених
       кроків) у stderr, exit 2: агент змушений виправляти.
     - Fail, stop_hook_active=true (повторний збій після спроби виправлення) →
       не exit 0 «мовчки», а
       {"continue": false, "stopReason": "npm run check still failing after 
       retry: <підсумок>"} + exit 0: сесія зупиняється
       з видимим повідомленням людині (Failure Protocol, крок 7). Дерево
       лишається зміненим → наступний хід перевіряє знову.
     - Обґрунтування: exit 2 без обмеження = нескінченний цикл; exit 0 при
       stop_hook_active = тиха «готово» з червоним check.
       Гучна зупинка з поясненням — єдиний варіант, що не має жодного з двох
       дефектів, без стану-лічильника.
     - Припущення, яке перевіряється першим (перед рештою роботи над Stop): що
       continue:false + stopReason у Stop hook справді
       зупиняє сесію з видимим повідомленням (мінімальний тимчасовий прототип із
       навмисним збоєм). Якщо ні — зупиняюсь і приношу
       вам запасні варіанти (напр. лічильник спроб у gitignored-файлі) на окреме
       погодження; без вашого рішення стан не додаю.

     5. spec-reviewer. Лише Read, Grep, Glob (без Bash/Edit/Write). Отримує в
     prompt список змінених файлів і diff; звіряє з AC у
     docs/spec.md та правилами CLAUDE.md (mesh, не camera; без OrbitControls; AC
     ID у назвах тестів; англійська). Видає звіт
     file:line — порушення — AC/правило; нічого не змінює.
