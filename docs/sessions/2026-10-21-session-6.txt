     Phase 5 — Deploy to GitHub Pages

     Context

     The app has no public URL. Phase 5 publishes it to GitHub Pages
     (https://irapolchanin.github.io/rotating-cube/) so the human can run the
     remaining
     manual checks (Firefox desktop, real touch device; docs/quality-gates.md
     §12) there.
     Deployment is not in docs/spec.md v1.0, so the spec is updated first, and
     nothing else starts until the human approves it.

     Findings that shape the plan:
     - vite.config.ts has no base. The only absolute path is the script tag in
       index.html, and Vite rewrites it at build time.
     - The only workflow is .github/workflows/ci.yml. It has contents: read,
       runs xvfb-run -a npm run check on every push, and has no deploy job.
     - E2E tests run against the dev server (playwright.config.ts), not against
       dist/.
     - .claude/settings.json has ask on git push*, so every push needs human
       confirmation.
     - docs/spec.md has no revision history section. §5 forbids stack
       substitutions without a spec update.

     Human clarifications (binding)

     1. Approving this plan does not approve the spec text. In Step 1 I show the
        exact docs/spec.md diff and wait for explicit approval before
        committing it.
     2. AC-16 must prove the live cube renders. It runs AC-1, AC-13 and the
        WebGL test against the public URL in Chromium and Firefox, under
        xvfb-run as in CI, with a bounded retry for Pages propagation. A curl
        check is not enough.
     3. I tell the human exactly when to enable Pages (Settings → Pages →
        Source: GitHub Actions). The human does it themselves. I do not do it.
     4. Before recording the two CI runs, I verify their commit SHAs and
        conclusions with gh run view.

     Step 1 — Spec v1.1 (STOP: show diff, wait for human approval of the text)

     Draft the docs/spec.md edit, show the exact diff, and do not commit until
     the human approves it. The edit is small and has four parts:
     - Header: Version 1.1, Last updated 2026-10-20. Add a short "Revision
       history" with v1.0 (initial) and v1.1 (deployment).
     - New NFR-9 (Deployment):
       - The app is published to GitHub Pages from main by GitHub Actions.
       - Deployment runs only after npm run check passes on that commit.
       - The public URL serves the same build that vite build produces.
     - New AC-16: the deployed URL responds 200 and contains
       div[data-testid="cube-scene"]. It is verified by a post-deploy smoke
       step, not by npm run check.
     - Supporting changes:
       - §5: add GitHub Pages and GitHub Actions as the hosting stack.
       - §6: add custom domain, preview deployments and a CDN/cache strategy as
         out of scope.
       - §8: add the assumption that Pages is enabled with Source = "GitHub
         Actions" and the repo visibility permits Pages.
       - §7.3: the Firefox and touch manual checks are run on the public URL.

     Commit: docs(spec): add deployment requirement NFR-9 and AC-16, bump to 
     v1.1

     Step 2 — Vite base path

     - Set base: './' in vite.config.ts.
     - Relative base chosen over /rotating-cube/ for two reasons:
       - it works under any project path;
       - the dev server and the existing Playwright baseURL stay unchanged.
     - Verify:
       - npm run build, then inspect dist/index.html for relative asset URLs.
       - Serve dist/ under a sub-path locally and confirm it loads. Use npx vite
         preview with --base, or a static server in the scratchpad.
     - Commit: build: use relative base for GitHub Pages

     Step 3 — Deploy workflow

     Create .github/workflows/deploy.yml. The existing ci.yml is left unchanged
     and keeps contents: read.
     - Trigger: push to main only, plus workflow_dispatch.
     - Top-level permissions: contents: read.
     - Concurrency: group pages, cancel-in-progress: false.
     - Job build:
       - Same setup as ci.yml (checkout, setup-node with .nvmrc, npm ci,
         Playwright browsers).
       - Run xvfb-run -a npm run check, so a broken commit is never deployed.
       - actions/configure-pages, then actions/upload-pages-artifact with path: 
         dist.
     - Job deploy:
       - needs: build, environment: github-pages.
       - Job-level permissions: pages: write, id-token: write. These are scoped
         to this job only.
       - actions/deploy-pages.
     - Post-deploy verification (AC-16), job verify-deployed, needs: deploy:
       - playwright.deployed.config.ts: baseURL from the env var DEPLOYED_URL
         (set to ${{ needs.deploy.outputs.page_url }}), no webServer, and the
         same chromium and firefox projects as playwright.config.ts (Firefox
         headed in CI).
       - It runs the existing tests for AC-1, AC-13 and the WebGL test against
         the public URL. I will identify the exact files in e2e/ (scene.test.ts,
         webgl.test.ts, smoke.test.ts) and reuse them, with no copies and no
         weakened assertions.
       - A new script e2e:deployed is not part of npm run check.
       - CI runs it as xvfb-run -a npm run e2e:deployed, after npx playwright 
         install --with-deps chromium firefox.
       - Bounded retry for Pages propagation: a small wait loop before the test
         run, for example up to 10 attempts at 15 s intervals, until the URL
         returns 200. It fails the job when the limit is reached. Test retries
         are not used to hide failures.
     - Pin action versions the same way ci.yml does.

     Human prerequisite, done by the human on GitHub: Settings → Pages → Source:
     "GitHub Actions". When: after Step 3 is committed locally and before the
     first push of deploy.yml to main (Step 4). I will stop and tell the human
     at that point, because the first deploy fails without it. I never enable it
     myself.
