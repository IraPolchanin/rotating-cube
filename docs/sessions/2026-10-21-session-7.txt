     # Rotating Cube

     [![CI](https://github.com/IraPolchanin/rotating-cube/actions/workflows/ci.y
     ml/badge.svg)](https://github.com/IraPolchanin/rotating-cube/actions/workfl
     ows/ci.yml)
     [![Deploy](https://github.com/IraPolchanin/rotating-cube/actions/workflows/
     deploy.yml/badge.svg)](https://github.com/IraPolchanin/rotating-cube/action
     s/workflows/deploy.yml)

     A small browser app that shows a 3D cube you rotate by dragging with a
     mouse or a
     finger. It exists to practise **harness engineering**: all application
     source code
     was written by Claude Code; the human engineer reviewed and approved plans
     but did
     not write or edit source files. The interesting part is the harness around
     the code,
     described below.

     **Live demo:** <https://irapolchanin.github.io/rotating-cube/>

     ## The application

     - React 19 + TypeScript (strict) + Three.js, built with Vite.
     - Horizontal drag rotates the cube mesh around Y, vertical drag around X
     (clamped to
       ±90°). The camera never moves and `OrbitControls` is banned by a lint
     rule.
     - Input uses Pointer Events with pointer capture; the canvas has
     `touch-action: none`.
     - A **Reset** button restores the initial orientation immediately.
     - The canvas fills the viewport and follows window resizes.

     Requirements and acceptance criteria (AC-1 … AC-16):
     [docs/spec.md](docs/spec.md).

     ## Run and check locally

     Requires Node.js 22 (see [.nvmrc](.nvmrc)).

     ```bash
     npm ci                                    # also sets
     core.hooksPath=.githooks (prepare script)
     npm run dev                               # Vite dev server on
     http://localhost:5173
     npx playwright install chromium firefox   # once, for the e2e tests
     npm run check                             # full quality gate
     ```

     | Script | What it does |
     |--------|--------------|
     | `npm run typecheck` | `tsc --noEmit` |
     | `npm run lint` | ESLint, zero warnings allowed |
     | `npm test` | Vitest unit tests (rotation logic) |
     | `npm run build` | `vite build` |
     | `npm run e2e` | Playwright on Chromium and Firefox (starts the dev server
     itself) |
     | `npm run check` | The five steps above, in order |
     | `npm run e2e:deployed` | AC-16 against the public URL; needs
     `DEPLOYED_URL`, not part of `check` |

     Last local run of `npm run check` (2026-10-21): all five steps passed, 20
     unit tests
     and 42 e2e tests (21 per browser).

     ## The harness

     Each mechanism, with its verification results and known gaps, is described
     in
     [docs/quality-gates.md](docs/quality-gates.md).

     | Layer | What it does | Where |
     |-------|--------------|-------|
     | Specification | Requirements, numbered acceptance criteria, testability
     contract (`data-testid` and `data-cube-r*` attributes), enforcement
     boundary. Changes need human approval. | [docs/spec.md](docs/spec.md) |
     | Agent instructions | Workflow (read spec → plan → approval → small steps
     → `npm run check`), commit convention, prohibitions (no weakening
     tests/lint, no `@ts-ignore`, no `--no-verify`). | [CLAUDE.md](CLAUDE.md) |
     | After-edit hook | `typecheck` + `lint` after every agent `Edit`/`Write`
     of code or JSON files; failures are fed back to the agent. |
     [scripts/agent-hook-check.mjs](scripts/agent-hook-check.mjs),
     [.claude/settings.json](.claude/settings.json) |
     | Pre-commit hook | `typecheck` + `lint` + `test` block a failing commit. |
     [.githooks/pre-commit](.githooks/pre-commit) |
     | Stop hook | Runs the full `npm run check` before the agent may finish a

     ### Known limitations

     Stated in full in [docs/quality-gates.md](docs/quality-gates.md); the main
     ones:

     - No branch protection or required status checks.
     - Pre-commit hook activation on a fresh clone is not verified.
     - Guardrails bind the agent only and have known pattern gaps (§5).
     - Manual browser and device checks are recorded as reported by the human.
     - `npm run check` runs twice per push to `main` (CI and Deploy).
