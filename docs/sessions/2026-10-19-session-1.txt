  # Rotating Cube — Project Specification

  Version: 0.1 — Draft
  Status: Awaiting approval
  Last updated: 2026-10-19

  ---

  ## 1. Project Goal

  Build a minimal browser-based application that displays an interactive 3D
  cube.
  The project exists to practise harness engineering: all application source
  code is
  written by Claude Code; the human engineer reviews and approves plans and
  changes
  but does not write or edit application source files directly.

  ---

  ## 2. Functional Requirements

  | ID   | Requirement |
  |------|-------------|
  | FR-1 | The application renders a 3D cube in a full-viewport WebGL canvas. |
  | FR-2 | The user can rotate the cube by clicking and dragging with a mouse. |
  | FR-3 | The user can rotate the cube by touch-dragging on touch-enabled
  devices. |
  | FR-4 | A visible Reset button restores the cube to its defined initial
  orientation. |
  | FR-5 | The rendering canvas resizes to fill the browser viewport when the
  window is resized. |

  ---

  ## 3. Acceptance Criteria

  ### Testability contract

  All automated E2E tests observe cube state through two DOM interfaces:

  - **Scene wrapper:** `div[data-testid="cube-scene"]` — wraps the `<canvas>`.
  - **Rotation attributes:** `data-cube-rx`, `data-cube-ry`, `data-cube-rz` on
  the
    scene wrapper, updated every render frame. Values are Euler angles in
  degrees
    (XYZ order), rounded to one decimal place (e.g. `"25.0"`).
  - **Reset button:** `button[data-testid="reset-button"]`.

  These attributes form a stable, implementation-neutral observation surface.
  Tests must not read Three.js internals or compare pixel screenshots.

  ### Initial orientation

  The cube's defined initial state is:
  `data-cube-rx="25.0"`, `data-cube-ry="-45.0"`, `data-cube-rz="0.0"`

  ### Criteria

  | ID    | Criterion | Verification method |
  |-------|-----------|---------------------|
  | AC-1  | On load, `div[data-testid="cube-scene"]` is present in the DOM. |
  E2E |
  | AC-2  | On load, the `<canvas>` inside the scene wrapper has a non-zero
  `clientWidth` and `clientHeight`. | E2E |
  | AC-3  | On load, `data-cube-rx`, `data-cube-ry`, `data-cube-rz` equal the
  initial orientation values. | E2E |
  | AC-4  | After a simulated horizontal mouse drag of ≥ 50 px on the canvas,
  `data-cube-ry` differs from its initial value. | E2E |
  | AC-5  | After a simulated vertical mouse drag of ≥ 50 px on the canvas,
  `data-cube-rx` differs from its initial value. | E2E |
  | AC-6  | After a simulated horizontal touch drag of ≥ 50 px on the canvas,
  `data-cube-ry` differs from its initial value. | E2E |
  | AC-7  | After a simulated vertical touch drag of ≥ 50 px on the canvas,
  `data-cube-rx` differs from its initial value. | E2E |
  | AC-8  | `button[data-testid="reset-button"]` is visible and enabled on load.
   | E2E |
  | AC-9  | After any drag that changes rotation, clicking the Reset button
  restores all three `data-cube-r*` attributes to initial values. | E2E |
  | AC-10 | At viewport 1280 × 720, `canvas.clientWidth` is within 2 px of
  `window.innerWidth`. | E2E |
  | AC-11 | After resizing the viewport from 1280 × 720 to 375 × 667,
  `canvas.clientWidth` updates to within 2 px of the new `window.innerWidth`. |
  E2E |
  | AC-12 | The rotation delta applied per pixel of horizontal drag is
  consistent: dragging 100 px produces twice the `data-cube-ry` change of
  dragging 50 px (±5 % tolerance). | E2E |
  | AC-13 | The application renders without JavaScript console errors on load. |
   E2E |

  | ID    | Requirement |
  |-------|-------------|
  | NFR-1 | TypeScript strict mode is enabled (`"strict": true` in

  | NFR-2 | `tsc --noEmit` reports zero errors. |
  | NFR-3 | ESLint reports zero errors (warnings are acceptable). |
  | NFR-4 | All Vitest unit tests pass. |
  | NFR-5 | All Playwright E2E tests pass. |
  | NFR-6 | The application loads and renders on localhost in under 5 seconds on
   a modern desktop browser. |
  | NFR-7 | The application runs without errors in the latest stable versions of
   Chrome and Firefox. |

  |------|------------|

  | UI framework | React |

  ## 6. Out of Scope

  - Backend, API, or server-side logic.
  - Authentication or user accounts.
  - Persistent state (localStorage, cookies, database).
  - Keyboard-based rotation controls.
  - Zoom, pan, or scale gestures.
  - Cube face textures, labels, or customisation UI.
  - Automatic / continuous rotation animation.
  - Mobile-specific UI chrome (e.g. dedicated toolbar).
  - Accessibility (ARIA, keyboard nav) beyond what React provides by default.
  - Support for browsers other than latest stable Chrome and Firefox.

  ## 7. Verification Strategy

  ### 7.1 Automated unit tests (Vitest)

  Target: pure logic that can be tested in isolation without a DOM or browser.

  | What is tested | Relevant AC |
  |----------------|-------------|
  | Euler angle calculation from pointer delta (px → degrees) | AC-4, AC-5,
  AC-12 |
  | Proportionality of rotation delta | AC-12 |
  | Reset function returns exact initial orientation values | AC-9 |

  ### 7.2 Automated E2E tests (Playwright)

  Target: full browser behaviour via the testability contract defined in §3.

  Covers: AC-1 through AC-13.

  Tests interact only with:
  - `data-testid` selectors
  - `data-cube-r*` attributes
  - Standard Playwright mouse/touch event APIs

  No pixel comparison (`toHaveScreenshot`) is used.

  ### 7.3 Manual browser checks

  Target: subjective or perceptual qualities that are impractical to automate.

  | What is checked | Relevant requirement |
  |-----------------|----------------------|
  | Cube appearance looks correct (no z-fighting, correct perspective) | FR-1 |
  | Rotation feels smooth and responsive during drag | FR-2, FR-3 |
  | Canvas visually fills the viewport with no gaps or scrollbars | FR-5 |
  | Application works on a real touch device | FR-3 |

  ### 7.4 Quality gate commands

  ```bash
  # Type-check
  npx tsc --noEmit

  # Lint
  npx eslint . --max-warnings 0

  # Unit tests
  npx vitest run

  # E2E tests (requires running dev server)
  npx playwright test

  All four commands must exit with code 0 before a change is considered
  complete.

  All automated E2E tests observe cube state through two DOM interfaces:

  - **Scene wrapper:** `div[data-testid="cube-scene"]` — wraps the `<canvas>`.
  - **Rotation attributes:** `data-cube-rx`, `data-cube-ry`, `data-cube-rz` on
  the

  degrees
    (XYZ order), rounded to one decimal place (e.g. `"25.0"`).
  - **Reset button:** `button[data-testid="reset-button"]`.

  These attributes form a stable, implementation-neutral observation surface.
  Tests must not read Three.js internals or compare pixel screenshots.
  E2E assertions on these attributes use Playwright auto-retrying assertions
  (e.g. `expect(locator).toHaveAttribute(...)`) rather than assuming synchronous
  DOM updates.

  E2E pointer interactions use Playwright's mouse API. Tests that cover touch
  input
  dispatch pointer events with `pointerType: "touch"` (simulated); behaviour on
  a
  real physical touch device is verified by manual check only.

  ### Initial orientation

  The cube's defined initial state is:
  `data-cube-rx="25.0"`, `data-cube-ry="-45.0"`, `data-cube-rz="0.0"`

  ### Rotation constraints

  - X rotation is clamped to the closed range **[-90°, 90°]**.
  - Y rotation is normalised to the half-open range **(-180°, 180°]**.
  - Z rotation is always `0.0`; user interaction does not affect it.

  |-------|-----------|--------------|

  "mouse"`) on the canvas, `data-cube-ry` differs from its initial value. | E2E
  |
  | AC-5  | After a simulated vertical pointer drag of ≥ 50 px (`pointerType:
  "mouse"`) on the canvas, `data-cube-rx` differs from its initial value. | E2E
  |
  | AC-6  | After a simulated horizontal pointer drag of ≥ 50 px (`pointerType:
  "touch"`) on the canvas, `data-cube-ry` differs from its initial value. | E2E
  |
  | AC-7  | After a simulated vertical pointer drag of ≥ 50 px (`pointerType:
  "touch"`) on the canvas, `data-cube-rx` differs from its initial value. | E2E
  |
  | AC-8  | `button[data-testid="reset-button"]` is visible and enabled on load.
   | E2E |
